1914 to 1989

Before learning

OCR is older than computers. For sixty years the trick was to make text easy for the machine (special fonts, magnetic ink, fixed forms) rather than make the machine good at text. Then came the first feature hierarchies that could learn.

1914OptophonePrinted letters turned into tones for blind readers.
1929Tauschek's reading machineA photo-sensor behind mechanical templates: a match when light passes through.
1951GISMORead typewritten letters aloud; led to the first OCR company in 1952.
1954Reader's DigestThe first business to install an OCR reader.
1958E-13B MICRMagnetic-ink digits for cheques. Still on every cheque.
1968OCR-A and OCR-BTypefaces designed for machines. OCR-B still runs along passport lines.
1976Kurzweil Reading MachineOmni-font OCR plus text-to-speech: any printed font, not one.

Scroll sideways · make the text easy for the machine, not the machine good at text

Wait, really?

The first reading machine predates the first electronic computer by about thirty years. Every system before 1974 could only read the fonts it had been built for.

1980
1980 · Kunihiko Fukushima · Biological Cybernetics

Neocognitron: feature cells, then shift-tolerant cells

1 cellper pattern, wherever it sits
Before
Pattern recognisers broke when the same shape appeared in a different position.
The breakthrough
Modelled on the visual cortex. S-cells detect local features with shared weights; C-cells pool nearby S-cells so a feature can move and the response stays. The pair repeats, each layer seeing larger patterns.
Result
Each final cell answered to one pattern wherever it appeared. The blueprint of every CNN, minus a way to train it end to end.
doi:10.1007/BF00344251
1989
1989 · LeCun, Boser, Denker et al. (Bell Labs) · Neural Computation

Train the convolutional hierarchy with backprop

5.0%error on real zip codes
Before
Digit recognisers relied on hand-engineered preprocessing and features.
The breakthrough
Feed the raw image straight in. Constrain the network with local receptive fields and strided 5x5 kernels whose weights are shared, so 64,660 connections need only 9,760 free parameters. Train every layer with Backpropagation on 7,291 real zip-code digits.
Result
5.0% error on 2,007 test digits, running on a DSP at over 10 digits a second. The earliest real-world network trained end to end.
doi:10.1162/neco.1989.1.4.541
Wait, really?

In 2022 Andrej Karpathy re-ran LeCun's 1989 network with modern tricks (Adam, augmentation, dropout) and cut its errors by about 60%, same tiny architecture. The idea was sound in 1989; the tools were missing.

Karpathy's write-up
1985
1985 to 1994 · Ray Smith (HP Labs Bristol) · open-sourced 2005, Google from 2006

Tesseract: spline baselines and an adaptive classifier

Top 31995 UNLV accuracy test
Before
OCR engines assumed straight, de-skewed lines and a fixed set of character models.
The breakthrough
Outlines of connected components are gathered into blobs, blobs into lines, and each line gets a quadratic spline baseline, so curved and skewed text needs no straightening. Words go through two passes: confident words from pass one train an Adaptive classifier on the fly, and pass two re-reads the unsure ones.
Result
Top three in the 1995 UNLV accuracy test. The adaptive classifier cuts errors 30 to 60% on long documents. The default free OCR engine for over a decade.

Wait, really?

Tesseract's adaptive classifier learns while it reads: after three confident examples of a character it starts recognising it. Read 'infinity' well and it reads the 'i' in the next word better.

1998

Recognising a symbol

One centred character, one label. The problem convolutional networks solved first, and the benchmark that made the field measurable.

1998
1998 · LeCun, Bottou, Bengio, Haffner · Proceedings of the IEEE

LeNet-5: let the network learn its own features

0.95%error on MNIST
Before
Recognisers were hand-designed feature extractors feeding a trainable classifier.
The breakthrough
5x5 convolutions with shared weights alternate with subsampling, about 60k parameters, all trained end to end by gradient descent. The forgotten half of the paper: a full cheque reader combining a segmenter, LeNet-5 and a language model, trained jointly.
Result
0.95% error on MNIST (0.8% with distortions). Deployed in NCR cheque readers, reading millions of US cheques.
doi:10.1109/5.726791
Wait, really?

MNIST was remixed from a 1992 US Census OCR contest. Systems trained on Census staff handwriting did worse on the contest's high-school test set, so LeCun, Cortes and Burges mixed both writer pools to make train and test match. A benchmark whose test set differs from its training set mostly measures that difference.

1998
1998 to 2019 · 60,000 train / 10,000 test, 28x28 · the benchmark

MNIST: from 12% error to 0.13%, then solved

0.13%13 errors in 10,000
Before
No shared, clean benchmark to compare recognisers on.
The breakthrough
Linear classifier 12.0%, k-NN 1.1%, LeNet-5 0.95%, SVM 0.68%, a GPU committee of deep nets 0.23% (2012), and ensembles reach 0.13%: 13 mistakes in 10,000, mostly ambiguous or mislabelled digits.
Result
Past the estimated 0.2% human error rate in 2012. But MNIST hands the model a pre-cropped, pre-centred symbol: no detection, no sequence, no layout. Real text is none of those things.

02

2006 to 2022

Reading real text

Find text anywhere in an image, then read whole lines without cutting them into characters. The longest era, and the one every production OCR pipeline is still built from.

2006
2006 · Graves, Fernandez, Gomez, Schmidhuber · ICML

CTC: train a sequence model without knowing the alignment

0frame-level alignment labels needed
Before
Training a sequence model needed a label for every frame, usually from an HMM.
The breakthrough
Add a blank symbol. The network emits one label per frame; collapse merges repeats and drops blanks, so '-CC-AAA-T-' becomes CAT. The loss sums the probability of every path that collapses to the target, computed with forward-backward dynamic programming.
Result
A BiLSTM with CTC beat HMM baselines on speech with no pre-segmentation. Still the decoding step of the fastest OCR recognisers in 2026.
doi:10.1145/1143844.1143891
2014
2014 / 2016 · Jaderberg et al. (Oxford) / Gupta et al. · NIPS DL Workshop / CVPR

Synthetic data: render millions of labelled words

9Mlabelled words, zero human annotation
Before
Real scene-text datasets held only a few thousand labelled words.
The breakthrough
Generate the labels instead. Synth90k renders words with random fonts, borders, colours and projective warps, blended onto natural images; the rendered word is the label. SynthText pastes text onto real scenes along predicted surfaces.
Result
Recognisers trained only on Synthetic data data reached state of the art on real benchmarks. MJSynth plus SynthText became the default training set for years.
arXiv 1406.2227
2015
2015 · Shi, Bai, Yao (HUST) · TPAMI 2017

CRNN: read a whole word as one sequence, no character boxes

8.3Mparameters, any word length
Before
Text was read character by character, or classified against a fixed word list.
The breakthrough
Convolutions turn the line into a feature map; each column becomes one time step. A BiLSTM reads the columns with context from both sides, and CTC turns per-column guesses into the string. Trained end to end from images and transcripts.
Result
8.3M parameters, any length, no segmentation. The reference architecture for line recognition: every later recogniser swaps one block.

2018
2018 · Ray Smith and contributors (Google) · Tesseract 4.0

Tesseract 4: read whole lines with an LSTM

100+languages, Apache-2.0
Before
Tesseract 3 segmented and classified characters one by one; broken or joined glyphs caused errors.
The breakthrough
CRNN's idea brought to the most widely used open-source engine. Convolutions, a summarising LSTM that collapses the height, forward and reverse LSTMs along the line, then a softmax trained with CTC and a dictionary-guided Beam search.
Result
Default engine from 4.0, 100+ languages out of the box, still maintained in 2026 and the baseline newer engines are measured against.

2017
2017 · Zhou, Yao et al. (Megvii) · CVPR

EAST: predict word geometry at every pixel, in one network

13.2 fpsone network, one merge step
Before
Text detection was a slow chain of proposals, filters and word splitting.
The breakthrough
A single fully convolutional network predicts, at every pixel, a text score plus the distances to the four box edges and an angle. One Non-maximum suppression step merges the overlapping boxes.
Result
F-score 0.78 on ICDAR 2015 at 13.2 frames a second. Weak spot: very long or curved text, which the receptive field cannot see end to end.
arXiv 1704.03155
2015
2015 · Jaderberg, Simonyan, Zisserman, Kavukcuoglu (DeepMind) · NeurIPS

Spatial Transformer: a layer that learns to un-warp its input

0warp labels needed
Before
CNNs tolerated small shifts but not rotation, scale or warping.
The breakthrough
A drop-in, differentiable module. A localisation network predicts transform parameters, a grid generator maps the output grid back into the input, and a sampler reads it bilinearly. Gradients flow through all three.
Result
Trained with class labels only, it learns to crop, scale and straighten by itself.
arXiv 1506.02025
2018
2018 · Shi, Yang, Wang, Lyu, Yao, Bai · IEEE TPAMI

ASTER: flatten curved text before reading it

20control points bend the word flat
Before
Recognisers read along a straight line, so curved and slanted text failed.
The breakthrough
A spatial transformer with a thin-plate spline places control points along the top and bottom of the text and flattens it. An Attention decoder then reads the straightened word.
Result
Large gains on curved and perspective benchmarks, and state of the art on regular text at the time.
doi:10.1109/TPAMI.2018.2848939
2019
2019 · Baek, Lee, Han, Yun, Lee (NAVER Clova) · CVPR

CRAFT: detect characters and the links between them

2heatmaps: region and affinity
Before
Word boxes failed on curved text, and real datasets had no character labels.
The breakthrough
Predict two heatmaps: where each character's centre is, and where neighbouring characters join. Character labels for real images are bootstrapped from a model trained on synthetic data (Weak supervision).
Result
State of the art on six benchmarks, including curved Total-Text and CTW-1500.
arXiv 1904.01941
2019
2019 · Baek, Kim, Lee et al. (NAVER Clova) · ICCV

What is wrong with scene text recognition? One protocol, four swappable stages

4stages, every combination tested
Before
Papers used different training data and test subsets, so results were not comparable.
The breakthrough
Split every recogniser into four stages (transformation, feature extraction, sequence modelling, prediction) and test every combination under one data and evaluation protocol.
Result
Much reported progress came from data and evaluation differences, not models. The open code became the standard baseline.
arXiv 1904.01906
2020
2020 · Liao, Wan, Yao, Chen, Bai · AAAI

DBNet: learn the binarisation threshold end to end

62 fpsF-measure 82.8 on MSRA-TD500
Before
Segmentation detectors used a fixed, hand-tuned threshold outside training.
The breakthrough
Predict a text probability map and a threshold map, and combine them with a steep, differentiable step (differentiable binarisation), so the threshold is learned. At inference only the probability map is needed.
Result
State of the art on five benchmarks, 62 fps with a ResNet-18. The detector inside PaddleOCR to this day.
arXiv 1911.08947
2017
2017 · Vaswani, Shazeer, Parmar et al. (Google) · NeurIPS

Transformer: attention alone, no recurrence

0recurrent steps
Before
Sequence models used recurrence, so training was serial and long-range context was hard to learn.
The breakthrough
Every Token looks at every other token through scaled dot-product attention, in parallel, with many heads at once. An Encoder builds context; a Decoder writes the output one token at a time while attending back to it.
Result
A new state of the art in translation at a fraction of the training cost. It became the architecture of every modern language and vision-language model.
arXiv 1706.03762
2020
2020 · Dosovitskiy, Beyer, Kolesnikov et al. (Google) · ICLR 2021

ViT: an image is worth 16x16 words

88.55%on ImageNet
Before
Vision models were built from convolutions; attention was bolted onto CNNs.
The breakthrough
Cut the image into 16x16 patches, flatten each into a vector, add a position, and feed the sequence to a plain transformer Encoder.
Result
With enough pretraining data it matched or beat the best CNNs. With too little it trailed them: scale beats built-in bias.
arXiv 2010.11929
2021
2021 · Li, Lv, Cui et al. (Microsoft) · AAAI 2023

TrOCR: a pretrained image transformer meets a text transformer

2.89CER on handwriting
Before
Recognisers paired a CNN with an RNN and often needed a separate language model.
The breakthrough
A ViT encoder reads the line image as patches; a pretrained text transformer Decoder writes word pieces while cross-attending to them. Both halves start from pretrained weights.
Result
F1 96.58 on printed receipts and CER 2.89 on IAM handwriting with no external language model.

2022
2022 · Du, Chen, Jia et al. (Fudan, Baidu) · IJCAI

SVTR: one visual model, no sequence model, still CTC

1 shotdecoding, no autoregression
Before
Accurate recognisers needed a slow sequence or language model on top of vision.
The breakthrough
Replace conv plus LSTM with a single vision transformer that mixes local and global patch context, then decode with CTC in one shot.
Result
Matches language-aware models on English, beats them on Chinese, and runs faster. PaddleOCR's recogniser descends from it.
arXiv 2205.00159
03

2017 to 2025

Understanding documents

The unit changes from a line to a whole page, and the output from a string to structure: LaTeX, HTML tables, Markdown, JSON. Position on the page starts to carry meaning, then models skip the OCR engine altogether.

2017
2017 · Deng, Kanervisto, Ling, Rush (Harvard) · ICML

im2latex: generate markup from pixels with attention

75%of formulas re-render exactly
Before
Maths OCR relied on hand-built grammars, and CTC assumed text runs strictly left to right.
The breakthrough
A CNN grid, a row encoder across it, and an Attention decoder that emits one LaTeX token at a time, looking wherever on the image it needs.
Result
Over 75% of test formulas re-render to the exact source image, against 15.6% for the classical system and 7.6% for a CTC model.
arXiv 1609.04938
2019
2019 · Zhong, ShafieiBavani, Jimeno Yepes (IBM) · ECCV 2020

PubTabNet: tables as HTML trees

+9.7TEDS points
Before
Table recognition lacked large datasets, and its metrics ignored the table's tree structure.
The breakthrough
568k table images paired with HTML. An encoder with two decoders: one writes the structure tags, one fills each cell. A new metric, TEDS, compares tables as trees.
Result
9.7 points better than the previous best. TEDS became the standard table metric and a third of today's headline document benchmark.
arXiv 1911.10683
2022
2022 · Nassar, Livathinos, Lysak, Staar (IBM Zurich) · CVPR

TableFormer: structure plus a box for every cell

96.75structure TEDS
Before
Image-to-HTML table models needed their own OCR decoder and gave no box per cell.
The breakthrough
A transformer decodes the structure tags while a second head predicts a bounding box for each cell, so cell text can be taken straight from the PDF or an OCR engine.
Result
Structure TEDS 96.75 on PubTabNet. The table model inside IBM's open-source Docling.
arXiv 2203.01017
2020
2020 · Xu, Li, Cui et al. (Microsoft Research Asia) · KDD

LayoutLM: put 2-D position inside the language model

+8.6F1 on form understanding
Before
Language models read documents as flat text and ignored where words sit.
The breakthrough
Every word Embedding gets its box coordinates added. Pretrain with masked words on millions of scanned pages, so 'Total' at the bottom right of a page means something different from 'Total' in a paragraph.
Result
The first joint text-and-layout pretraining. Form understanding jumped from 70.7 to 79.3 F1.
arXiv 1912.13318
2022
2022 · Kim, Hong, Yim et al. (NAVER) · ECCV

Donut: pixels in, JSON out, no OCR engine

0OCR engines in the loop
Before
Document understanding depended on an OCR engine whose errors propagated.
The breakthrough
A Swin Encoder reads the page and a text Decoder writes the answer directly as structured tokens. Pretrained on a synthetic document generator (SynthDoG), so new languages need no real labels.
Result
State-of-the-art speed and accuracy on classification, receipt extraction and document VQA, about twice as fast as the OCR-based LayoutLMv2.
arXiv 2111.15664
2023
2023 · Blecher, Cucurull, Scialom, Stojnic (Meta AI) · arXiv

Nougat: write a scientific page as Markdown and LaTeX

1 imageto a full Markdown page
Before
OCR recovered characters from papers but lost equations and structure.
The breakthrough
Donut's recipe trained on arXiv papers paired with their source, so the model writes headings, lists and equations from the image alone.
Result
Beat existing tools at converting papers, especially equations. Works on scans and books with no text layer.
arXiv 2308.13418
2024
2024 · Wei, Liu, Chen et al. (StepFun, Megvii et al.) · arXiv

GOT-OCR 2.0: one model for every kind of character

580Mparameters, one model
Before
OCR pipelines were brittle and general vision-language models were huge and poor at dense text.
The breakthrough
A 580M encoder-decoder trained on text, formulas, tables, sheet music, molecules and charts. Point at a region with a box or a colour and it reads just that.
Result
State-of-the-art page-level OCR in English and Chinese at 580M parameters. Later used as a teacher to distil PaddleOCR's detector.
arXiv 2409.01704
2025
2025 · Poznanski, Soldaini, Lo et al. (Allen AI) · arXiv

olmOCR: anchor on the PDF's text, then reward passing unit tests

< $200per million pages
Before
Frontier models extracted PDF text well but cost thousands per million pages.
The breakthrough
Give a 7B VLM the page image plus the PDF's own text layer as an anchor. Version 2 renders synthetic HTML pages so the ground truth is exact, then trains with Reinforcement learning on unit tests ('is this table cell right?').
Result
Under $200 per million pages, about 1/32 of the batch price of a frontier API. Version 2 among the best open models at release.
arXiv 2502.18443
2025
2025 · Wei, Sun, Li (DeepSeek-AI) · arXiv

DeepSeek-OCR: a page image as compressed context

10xtext compressed into vision tokens
Before
A page of text costs thousands of language-model tokens; context is expensive.
The breakthrough
Turn the question around: how few vision tokens can carry a page of text? A compressing encoder squeezes the page; a small Mixture of experts decoder expands it back.
Result
About 97% precision when there are under 10 text tokens per vision token, about 60% at 20.
arXiv 2510.18234
Wait, really?

DeepSeek-OCR suggests a picture of text can be a cheaper way to store it than the text itself, at least for a language model: one image token holding ten words.

2020 to 2026

Inside PaddleOCR, and what came after

PaddleOCR is the best map of the field because it absorbed most of the papers above: DB for detection, CRNN then SVTR for recognition, CTC for decoding, GOT as a teacher. Then a small vision-language model, then models that beat it.

2020
2020 · Du, Li, Guo et al. (Baidu) · arXiv

PP-OCR: a 3.5M-parameter OCR system from 19 strategies

3.5Mparameters, whole system
Before
Accurate OCR was large and GPU-bound; phones and CPUs needed tiny models.
The breakthrough
Three stages (DB detection, a direction classifier, CRNN recognition), each shrunk with a list of strategies: light backbones, Distillation, pruning, quantisation, and lots of data.
Result
3.5M parameters for 6,622 Chinese characters, trained on 17.9M recognition images.
arXiv 2009.09941
2025
2025 to 2026 · Baidu PaddleOCR team · PP-OCRv5 / v6

PP-OCRv5/v6: train with two heads, ship one

5.2xfaster on CPU (Baidu-reported)
Before
Attention decoders read better but are slow; CTC is fast but learns weaker context.
The breakthrough
An attention branch shares the backbone during training and teaches it sequence context, then is thrown away. Only the fast CTC head ships. The detector is distilled from GOT-OCR 2.0.
Result
1.5M to 34.5M parameters, 50 languages in one model; the medium tier is 5.2x faster than v5 on CPU. CTC also gives a per-line Confidence score that generative models do not.

OvisOCR3: distil five specialist teachers into one 0.8B model

96.74from a 0.8B model
Before
Specialist models win single tasks, but running five models in production is costly.
The breakthrough
Train five 4B teachers (parsing, OCR, key fields, figures, cross-page tables), then On-policy distillation into one 0.8B student: the student writes, the teachers score its tokens. Finish with Reinforcement learning using a reward per domain.

Before
Extraction meant OCR followed by rules: find 'Invoice No', look right, take the next token.
The breakthrough

Before

Bleeding edge · an open question

what next? · an AI agent edits weights directly · Weight-Space Programming

Could you program a model by editing its weights?

0.013%of weights changed
Before
Changing a model's behaviour means collecting data and running fine-tuning. Every fix is another training run.
The breakthrough
Following Takehi et al. (2026), an AI agent inspects Qwen3-VL-2B and writes small, targeted weight edits by hand, keeps the ones that help on a dev set and checks them on a held-out test set. No training run, no new data.
Result
Three edits touching 0.013% of the weights raised dev-set fields from 355 to 382 of 495. On the held-out test set the gain is only 153 to 156 of 198, so the honest answer for now is: maybe. If it holds up, fixing a model could look more like editing code than retraining it.

What it means in practice

Use each generation for what it is best at

The grounding and audit layer

Pipeline OCR

PP-OCRv6: DB + SVTR + CTC

Per-word boxes, per-line confidence, no invented text, CPU speed.

The structure layer

Document VLM

PaddleOCR-VL, OvisOCR3, TeleOCR

Full pages to Markdown or JSON, with tables, formulas and reading order, on one GPU.

The judgement layer

Frontier model

General-purpose large models

Reasoning over messy documents. Lower raw parsing scores, higher cost.

Guardrails for generative OCR

  • Compare character-level agreement between generative output and a pipeline OCR.
  • Require grounding coordinates for every extracted field.
  • Validate with business rules: totals, checksums, date formats.
  • Route low-agreement pages to a person. Handwriting is still the weak spot for every model.

Public benchmarks pick the candidates. Only your own documents, scored field by field, pick the winner.
